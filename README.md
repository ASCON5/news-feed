# news-feed

[![tests](https://github.com/ASCON5/news-feed/actions/workflows/tests.yml/badge.svg)](https://github.com/ASCON5/news-feed/actions/workflows/tests.yml)

Бот, который сам собирает свежие новости на русском и публикует их в Telegram-канал:
IT и техника, искусственный интеллект и роботы, программирование и open source, наука и интересные факты,
игры и немного главного из мира. Работает бесплатно на GitHub Actions, без своего сервера.

## Что умеет

- Собирает новости из 19 русскоязычных RSS-источников (список в `sources.yml`).
  Поддерживает также публичные Telegram-каналы, CTFtime, Codeforces и Devpost.
- Убирает дубли (одинаковые ссылки и похожие заголовки), рекламу, викторины и тесты.
- Одну и ту же историю из разных источников публикует один раз, даже если заголовки написаны по-разному:
  сравнивает основы слов, редкие слова и имена (Орёл, Capcom, PHP) весят больше частых. Остальные источники
  попадают в строку «Также писали», а повтор за следующие сутки не выходит.
- Пишет пост так, чтобы его было удобно читать: заголовок, 2–3 законченных предложения без обрывков
  и хвостов вроде «Читать дальше», теги и ссылка на оригинал.
- Публикует посты с фото, если оно нашлось; если Telegram не принял картинку, шлёт пост без неё.
- Ставит теги по теме: `#ИИ`, `#роботы`, `#опенсорс`, `#разработка`, `#техника`, `#космос`, `#наука`, `#игры` и др.
- Чередует источники: первыми идут те, что дольше всех не попадали в канал, чтобы редкие не тонули среди частых.
- Лимиты: до 5 постов за запуск и 30 за сутки. У политики свой потолок за сутки: `#мир` 4, `#узбекистан` 2.

## Как это устроено

```
GitHub Actions (по расписанию) -> newsbot.py -> Telegram-канал
                                      |
                         ветка state, state.json (память: что уже отправлено)
```

Файлы: `newsbot.py` (вся логика), `sources.yml` (источники и настройки),
`.github/workflows/news.yml` (расписание), `.github/workflows/tests.yml` (тесты при каждом изменении),
`tests/` (автотесты).

Память бота хранится в отдельной ветке `state`, чтобы её коммиты не засоряли историю `main`.
Перед запуском workflow кладёт её в `data/state.json`, после запуска сохраняет обратно. Руками не править.

## Запуск с нуля

1. Создай бота у `@BotFather`, скопируй токен. Создай канал и добавь бота админом с правом публикации.
2. В репозитории: Settings -> Secrets and variables -> Actions, добавь секреты
   `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` (`@имя_канала` для публичного).
3. Actions -> news -> Run workflow с галочкой `Пробный режим`: бот ничего не публикует, а печатает в лог,
   что отправил бы. Так видно, какие источники работают.
4. Запусти без галочки. Первый боевой запуск только запоминает текущие записи и ничего не публикует.
5. Дальше бот работает сам по расписанию из блока `schedule` в `news.yml`
   (каждый час с 06:17 до 23:17 по Ташкенту).

Остановить бота: Actions -> news -> `...` -> Disable workflow.

## Как добавить источник

В `sources.yml`, раздел `sources`, одна строка:

```yaml
- {name: Хабр, type: rss, url: "https://habr.com/ru/rss/news/?fl=ru", tag: IT}
- {name: BBC, type: rss, url: "https://feeds.bbci.co.uk/russian/rss.xml", tag: мир, topics: false}
- {name: CodeCamp, type: telegram, channel: campcode, preview: false, tag: разработка}
```

Типы: `rss`, `telegram` (только публичные каналы с веб-превью), `ctftime`, `codeforces`, `devpost`.
Для соревнований и грантов добавь `kind: opportunity`. Отключить источник: `enabled: false`.
Фото у источника отключается так: `images: false`. С `topics: false` в посте будет только тег источника.
Потолок постов за сутки для тега источника задаётся в `settings.tag_limits_per_day`.

## Тесты

```
pip install -r requirements.txt
python -m unittest discover -s tests
```

На GitHub тесты запускаются сами при каждом изменении в `main` и в pull request.

## Ограничения

- Расписание GitHub Actions неточное: запуски опаздывают, бывает на несколько часов,
  а часть запусков GitHub пропускает.
- В публичном репозитории GitHub может отключить расписание при долгой неактивности.
  Чтобы этого избежать, бот сохраняет память в ветку `state` и подтверждает расписание через API,
  но гарантии нет.
- Текст поста берётся из анонса источника как есть, бот его не пересказывает.
- Сайты иногда меняют адрес RSS. Сломанный источник не мешает остальным, а в логе запуска
  появляется предупреждение `::warning::` с его именем.
- Репозиторий публичный: токены и секреты хранятся только в GitHub Secrets, не в коде.
